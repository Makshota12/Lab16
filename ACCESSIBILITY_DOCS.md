# Документация по доступности (Лабораторная работа 16)

## Обзор
Этот документ описывает реализацию доступных пользовательских интерфейсов в приложении Android для Лабораторной работы 16. Проект демонстрирует лучшие практики поддержки пользователей с различными потребностями, включая тех, кто использует скринридеры (TalkBack), нуждается в высокой контрастности или требует увеличенных областей касания.

## Описание файлов и классов

### 1. AccessibilityManager.kt
Файл `AccessibilityManager.kt` содержит класс `AccessibilityManager` и вспомогательную структуру `AccessibilityState`.

**AccessibilityManager**
Класс `AccessibilityManager` отвечает за взаимодействие с системными службами Android для получения текущих настроек доступности. Он инкапсулирует логику проверки различных параметров, таких как наличие работающего скринридера (`isScreenReaderEnabled`), текущий масштаб шрифта системы (`getFontScale`), включен ли режим высокой контрастности (`isHighContrastEnabled`) и требуется ли уменьшение анимации (`isReduceMotionEnabled`). Также класс предоставляет метод `getMinimumTouchTargetSize`, который динамически рекомендует минимальный размер кликабельных областей (48dp для доступности или стандартные 44dp).

**AccessibilityState**
В этом же файле определен data class `AccessibilityState`, который хранит снимок текущих настроек доступности, и Composable функция `rememberAccessibilityState`. Эта функция подписывается на изменения конфигурации системы и автоматически обновляет состояние UI, позволяя компонентам мгновенно реагировать на включение TalkBack или изменение размера шрифта без перезагрузки приложения.

### 2. AccessibleComponents.kt
Файл `AccessibleComponents.kt` представляет собой библиотеку адаптированных UI-компонентов, обеспечивающих соответствие стандартам доступности. В нем реализованы `AccessibleButton`, который принудительно устанавливает минимальную область касания в 48dp и формирует расширенные описания для скринридеров; `AccessibleTextField`, который поддерживает динамическое масштабирование шрифта и озвучивает количество введенных символов с ошибками валидации; `AccessibleSwitch`, объединяющий переключатель и его метку в единую кликабельную область с понятной семантикой состояния; и `AccessibleCard`, который автоматически адаптирует свою роль (кнопка или контейнер) и внешний вид в режиме высокой контрастности.

### 3. AccessibilityDemoScreen.kt
Файл `AccessibilityDemoScreen.kt` содержит основной экран приложения, демонстрирующий работу всех созданных компонентов.

**AccessibilityDemoScreen**
Это Composable функция, которая собирает все элементы в единый интерфейс. Она демонстрирует примеры использования полей ввода с валидацией, переключателей настроек, списка новостей и кнопок действий. Экран также включает специальную панель "Accessibility Status", которая в реальном времени отображает, какие функции доступности сейчас активны на устройстве (например, показывает галочку напротив "TalkBack", если он включен). Структура экрана использует `Column` с вертикальной прокруткой, обеспечивая доступность всего контента даже на небольших экранах или при очень крупном шрифте.

### 4. MainActivity.kt
Файл `MainActivity.kt` является точкой входа в приложение.

**MainActivity**
Класс наследуется от `ComponentActivity` и отвечает за начальную инициализацию Jetpack Compose. Внутри `setContent` он применяет тему приложения `Lab16Theme` и размещает основной контейнер `Scaffold`. В отличие от стандартного шаблона, здесь вызывается `AccessibilityDemoScreen`, который и содержит всю логику лабораторной работы. Код здесь минималистичен и служит только для запуска демонстрационного экрана в безопасной области экрана (`enableEdgeToEdge` и обработка `innerPadding`).

## Детали реализации

### Семантика
Мы используем `Modifier.semantics` для обогащения дерева пользовательского интерфейса службами доступности. Свойство `contentDescription` описывает визуальный контент, а `stateDescription` описывает динамическое состояние, например, количество введенных символов или состояние переключателя. Свойство `role` определяет тип элемента для правильного поведения в TalkBack, а `customActions` добавляет специфические действия, доступные через локальное контекстное меню в TalkBack.

### Визуальная доступность
Для обеспечения визуальной доступности компоненты проверяют флаг `highContrastEnabled` для переключения на цветовые палитры с более высоким контрастом, например, используя более темный фон или границы с более высокой непрозрачностью. Все интерактивные элементы принудительно устанавливают минимальный размер 48dp с помощью `defaultMinSize`. Размеры текста умножаются на `fontScale`, чтобы уважать системные настройки размера шрифта.

## Тестирование
Инструментальные тесты находятся в файле `AccessibilityComponentsTest.kt`. Они используют `composeTestRule` для проверки семантических свойств, таких как `ContentDescription`, `Role` и `ToggleableState`. Также тесты проверяют, что размеры областей касания соответствуют требованиям.
